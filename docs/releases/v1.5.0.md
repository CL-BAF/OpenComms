# OpenComms v1.5.0

OpenComms v1.5.0 brings durable work coordination to the shared browser and native console while preserving the identity and permissions of linked host sessions.

- Tasks distinguish queued, delivered and acknowledged messages from execution. Acceptance requires criterion-matched evidence, independent review and an explicit operator decision. Revisions, ownership, dependencies and bounded review rounds guard transitions.
- Project-local team templates retain roles, prompts, runtime/model requirements and budgets. Operators explicitly choose each entry to link or launch. Manual task handoffs preserve history, evidence and context and refuse running or uncertain work.
- Search project proposals, accepted decisions, verified findings, questions and rejected approaches. Compact handoffs reference retained context and active tasks.
- Browser and native GUI actions share validated backend operations, project boundaries and request identifiers. Integration onboarding separates detected applications, configuration checks, runtime contact and verified roundtrips. Host permission controls allow one pending request once or reject it.
- Emergency coordination pauses persist across restart and project switches. Resume unpauses only channels paused by that stop. Delivery budgets apply to queued handovers and retries; uncertain host acceptance remains visible without automatic replay.
- Installed MCP and hook entries ship as standalone bundles. Gemini hooks and manual editor profiles extend setup options. Explicitly managed OpenCode or operator-configured ACP sessions support checked identities and optional detached Git worktrees; linked sessions remain user-owned.
- Reliability fixes preserve malformed state before recovery, save queue cleanup even without a dispatched batch, prevent duplicate managed creation, redact known coordinator credentials and reject remote or inactive permission records before accessing a local runtime. Redundant comments and unreachable internal code were removed.

Back up project `.opencomms` state and integration configuration before upgrading, stop writers, and upgrade every coordinator/plugin instance before resuming. Legacy task replies migrate as receipt evidence, never verified completion. Existing channel messages, archives and linked host conversations are retained.

The Windows browser-console installer and native Tauri installer are distinct packages. Native assets, protocol tests and local GUI fixtures do not establish packaged WebView/installer operation; release-specific builds and installer smoke tests must verify those artifacts. Builds are unsigned unless the published release explicitly states otherwise.

Authenticated vendor/model interoperability remains unverified by the protocol fixtures. Remote managed control and Codex App Server support are unavailable. Automatic dependency scheduling, model fallback and worktree merging are not implemented. Shared-tree ownership is advisory, usage/cost stays unknown without actual host telemetry, and coordinator budgets do not impose a hard spend cap on already running host work. The GUI updater remains disabled. See [capabilities](https://github.com/CL-BAF/OpenComms/blob/v1.5.0/docs/CAPABILITIES.md) and [live verification prerequisites](https://github.com/CL-BAF/OpenComms/blob/v1.5.0/docs/INTEGRATION_VERIFICATION.md).
